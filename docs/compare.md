# 並行照合（opentax compare）

他のソフトで作った申告書と、OpenTax の結果を、帳票・欄ごとに比べます（DESIGN.md §27）。
OpenTax に少しずつ置き換えるとき、「同じ数字になるか」「違うならどちらが法令どおりか」を確かめるための道具です。

```
opentax compare <相手> <OpenTax> [--balance 残高試算表.csv] [--csv 結果.csv] [--html 結果.html] [--summary-json 要約.json]
```

| 引数 | 渡せるもの |
|---|---|
| 相手 | e-Tax の申告データ（.xtx・.xml。どのソフトで作っても同じ形）／控えを AI が読んだ値の JSON（下の形） |
| OpenTax | OpenTax が作った .xtx／OpenTax の入力 JSON（法人・消費税・所得税・相続税。その場で計算する。公式XSD のキャッシュが要る） |

- 比べるのは両方にある帳票だけ。片方にしかない帳票は名前だけ一覧に出します（例: OpenTax がまだ作らない内訳書）。
- 「0」と「空欄」は同じとみなします（ソフトによって 0 の欄を書くか省くかが違うため）。
- 違いのある欄には、帳票フィールド仕様書の計算式と、両方の値を式に当てはめた結果（「相手は式と違う」など）を付けます。式と合わない側から調べてください。
- 法人の地方税は e-Tax にないので、OpenTax の地方税の一覧（第六号様式・第二十号様式）と、相手の JSON の `local` を欄番号で比べます。
- 結果のファイルには会社の金額が入ります。手元にだけ置いてください。
- 違いがあっても終了コードは 0 です（違いは結果として書き出します）。

## 控えの PDF から比べるとき

この道具は PDF を読みません（読み取りは AI の役、計算と照合はプログラムの役。DESIGN §24）。
控えの PDF は AI に読ませて、次の形の JSON にしてから渡します。

```json
{
  "kind": "opentax-values",
  "source": "控え.pdf",
  "forms": {
    "HOA420": [
      {"line": "4", "column": "総額", "name": "納税充当金", "value": "70,000"},
      {"tag": "ARB00010", "value": "△1,200,000"}
    ]
  },
  "local": [
    {"form": "第六号様式", "no": "⑱", "value": "70,000"}
  ]
}
```

- `forms` のキーは e-Tax の帳票ID（別表一 = HOA112、別表四（簡易様式）= HOA420 など。帳票フィールド仕様書の様式ID）。
- 欄は `tag`（仕様書のタグ）か、`line`（行番号）＋`column`（列。「総額」「留保」など一部でよい）＋`name`（項目名の一部。任意）で指します。
  1つの欄に決まらない行は「欄に当てられなかったもの」として残し、推し量って合わせません。
- 同じ行に本書きと外書き（小さく書く数字）があるときは、指定がなければ本書きとみなします。外書きは `column` か `name` に「外書」と書きます。
- 金額は「70,000」「△1,200,000」のような書き方でもかまいません。
- 控えから読んだ値は、読んだ欄だけを比べます（OpenTax にだけある欄・帳票は数えません）。全部の欄を読んだときだけ `"complete": true` を付けると、OpenTax にだけある欄も「OpenTaxだけ」として数えます。
- `local` の `form` は「第六号様式」「第二十号様式」「第六号様式別表九」、`no` は様式の欄番号（⑦・（53）・7 のどれでも）。
